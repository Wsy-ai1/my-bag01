# 02 · 取图与标定操作手册

## 一、取图流程（对应讲义 3.2）

代码在 `src/io/hikrobot/hikrobot.cpp`，顺序就是讲义要求的口述流程：

| 步骤 | SDK 调用 | 说明 |
| --- | --- | --- |
| 1. 查找设备 | `MV_CC_EnumDevices(MV_GIGE_DEVICE\|MV_USB_DEVICE, &list)` | 遍历设备，按 `vid_pid` 匹配 USB 相机 |
| 2. 创建句柄 | `MV_CC_CreateHandle(&handle, devInfo)` | `handle` 是后续所有调用的凭证 |
| 3. 打开设备 | `MV_CC_OpenDevice(handle)` | 独占访问；被占用会失败 |
| 4. 设置参数 | `MV_CC_SetEnumValue/SetFloatValue/...` | 关自动曝光、写曝光与增益、像素格式、帧率 |
| 5. 开始取流 | `MV_CC_StartGrabbing(handle)` | 之后相机持续往缓冲区送图 |
| 6. 取一帧 | `MV_CC_GetImageBuffer(handle, &out, timeout)` | 拿到 `out.pBufAddr` + `out.stFrameInfo` |
| 7. 转 OpenCV | `cv::cvtColor(raw, bgr, COLOR_BayerRG2BGR)` | Bayer 8bit → BGR，`cv::Mat` 零拷贝包一层再转 |
| 8. 入队 | `LatestFrame::push()` | 容量 1 的队列，识别端永远拿最新帧 |
| 9. 归还缓冲区 | `MV_CC_FreeImageBuffer(handle, &out)` | **必须调用**，否则几次之后就不再出图 |

收尾：`MV_CC_StopGrabbing` → `MV_CC_CloseDevice` → `MV_CC_DestroyHandle`。

### 参数含义（讲义表 1）

| 参数 | 含义 | 调的时候注意 |
| --- | --- | --- |
| Exposure（曝光） | 传感器感光时长，单位 ms（SDK 内部 µs） | 太小画面暗；太大运动拖影、帧率下降。运动场景先降曝光再靠增益补 |
| Gain（增益） | 信号放大倍数，单位 dB | 提亮但噪声变大，一般 ≤ 20 |
| Frame Rate | 每秒帧数 | 受曝光时间上限约束：曝光 10ms → 最多 100fps |
| Pixel Format | 数据排列（Bayer/Mono/RGB） | 代码按 `pixel_format` 转换，填错就花屏/报"不支持" |
| Timestamp | 出图时刻 | 代码用 `steady_clock` 记录，后续与云台姿态对齐 |

### 运行

```bash
# 实时显示 + 帧率 + 按键
./build/camera_test --config-path=configs/camera.yaml --display

# 无显示器（SSH）：只统计帧率，跑 300 帧退出
./build/camera_test --frames 300 --no-display

# 每秒自动存一张原图（做数据集或看曝光稳定性）
./build/camera_test --save-every 1.0 --save-dir=assets/calibration_imgs
```

按键：`q`/`Esc` 退出，`s` 保存当前**原图**（未加任何叠加文字，直接可拿去标定）。

> 提交里要的"能看到画面和帧率"的截图：`--display` 后截屏即可，左上角黑底绿字就是 FPS 与帧号。

## 二、标定操作

### 2.1 先确认标定板（最容易翻车的一步）

```bash
# 数一遍圆点：几列 × 几行
# 量圆心间距：卡尺量 2~3 个间距取平均（单位 mm）
cat configs/calibration.yaml
```

配置里的 `pattern_cols / pattern_rows / center_distance_mm` 必须和手里那块板**完全一致**。
讲义特别提醒：参考仓库 `capture.cpp` 写死 10×7，`calibration.yaml` 却可能是别的尺寸——不要盲抄。

如果没有 10×7 圆点板：可以用棋盘格，但要改 `calib::detectGrid` 里的 `findCirclesGrid` 为 `findChessboardCorners`（本工程未内置，属于额外改动）。

### 2.2 采图（15~25 张）

```bash
./build/capture_calib --config-path=configs/camera.yaml \
    --calibration-config=configs/calibration.yaml \
    --out-dir=assets/calibration_imgs --target=20
```

按键：`s` 保存（只有检测到完整圆点阵才允许），`a` 自动连拍开关，`q` 退出。

采集要求（讲义 4.4）：

- 固定焦距、光圈、分辨率，全程不动
- 15~25 张，覆盖中心 + 四角 + 边缘
- 距离和倾角都要变，不要全是正对
- 整块板在画面内、圆点不被遮挡
- 避免反光、过曝、失焦、运动模糊
- 不要连续拍一堆几乎一样的

无界面/自动：

```bash
./build/capture_calib --no-display --auto=800 --target=20
```

### 2.3 标定

```bash
./build/calibrate_camera assets/calibration_imgs \
    --config-path=configs/calibration.yaml
# 想排查检测问题：
#   --debug-dir=output/detections     把每张的检测结果存图
#   --show                            逐张弹窗
```

程序会打印：

```
camera_matrix:
  [ fx  0  cx ]
  [ 0   fy cy ]
  [ 0   0   1 ]
distortion_coefficients (k1 k2 p1 p2 k3 ...): [ ... ]
rms / mean / max reprojection error
每张图的误差（超过阈值的标 <-- 偏大，考虑剔除）
```

结果写入 `configs/camera_intrinsics.yaml`（含 K、D、分辨率、误差、用到的图片名、逐图误差）。

### 2.4 判断结果可不可信（讲义 4.6）

- 成功识别大部分图（程序里能看到 `[ok] ... 找到 70 个圆心`）
- `fx`、`fy` 为正且接近（相差 >10% 要怀疑）
- `cx ≈ 宽/2`、`cy ≈ 高/2`
- 平均重投影误差 < 0.5 px 很好，< 1 px 可用
- 单张误差明显大的（比如 > 2 px）删掉重标
- 去畸变后看**画面边缘的直线**（门框、桌沿）是否变直

### 2.5 去畸变对比（提交材料）

```bash
./build/undistort_compare --intrinsics=configs/camera_intrinsics.yaml \
    --input=assets/calibration_imgs/calib_0001.png --output=output
```

生成 `*_before.png`、`*_after.png`、`*_compare.png`（左右拼接带标注）。
`--alpha 1` 保留全部像素（有黑边），`--alpha 0` 裁掉黑边。

### 2.6 什么时候必须重标

换相机、换镜头、动焦距/光圈、改分辨率、改工作距离导致对焦变化——都要重来。
